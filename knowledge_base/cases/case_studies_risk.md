# 客诉案例库（复杂与风险场景）

> 高风险、跨部门、易踩坑的复杂案例。每条标注：风险点、处理红线、复盘要点。

## 案例 R-001 群体投诉（同一商品多人中招）

**场景**：某品牌保温杯 3 天内收到 12 起「内胆异味」投诉。
**处理**：触发 L4 群体投诉 → 客诉经理 2 小时内成立专项组 → 梳理受影响订单 → 统一口径（免费换新或退款）→ 下架同批次 → 法务审核方案 → 7 天完成全部闭环 + 回访。
**风险点**：处理口径不一致会引发更大舆情；必须统一方案 + 法务审核。
**依据**：POL-025、《投诉升级 SOP》群体投诉

## 案例 R-002 食品安全升级（疑似腹泻）

**场景**：用户食用自热锅后腹泻，要求赔偿医疗费。
**处理**：按 A 级安全事件 → 2 小时内上报食品安全组 + 法务 → 收集商品批次、剩余样品 → 建议用户就医并保留凭证 → 全额退款 + 按规定赔偿 + 送检 → 涉医疗费用转法务与商家协商，客服不承诺具体金额。
**风险点**：医疗费赔付属法务范畴，一线不得承诺；送检是标准动作。
**依据**：POL-018、《食品 SOP》2

## 案例 R-003 舆情风险（短视频曝光）

**场景**：用户称已把「平台售卖假货」视频发到短视频平台，播放量在涨。
**处理**：10 分钟内升级客诉经理 + 公关 → 公关对接视频处理（不强行删帖）→ 客服经理 2 小时内直接沟通用户 → 快速给出实质方案（验真 + 退款/补偿）→ 24 小时内出处理说明。
**风险点**：强行删帖会激化；一线禁止回应媒体；验真结论必须真实。
**依据**：POL-025、《投诉升级 SOP》媒体投诉

## 案例 R-004 职业索赔人

**场景**：同一地址多账号短期内多次购买临期食品并投诉过期，要求「退一赔十」。
**处理**：风控识别关联账号 → 人工复核（核对批次生产记录：商品并未过期）→ 拒绝「退一赔十」主张，按规则退款或补偿 → 全程留痕，不辱骂不争执。
**风险点**：商品未过期则不构成欺诈，不适用惩罚性赔偿；与用户讲规则而非情绪。
**依据**：POL-005、POL-018、《生鲜 SOP》风控

## 案例 R-005 高价值商品调包争议

**场景**：用户退货的相机 SN 与发货记录不一致，且外观有明显更换痕迹。
**处理**：仓库验收发现 SN 不匹配 → 暂停退款 → 客服沟通（附验收照片）→ 按规则商品退回用户或折价处理 → 涉及欺诈的可报警。
**风险点**：SN 核验是 3C 售后红线，缺失即拒绝；沟通要有证据支撑。
**依据**：《售后 SOP》3C 数码售后细则、《退款 SOP》资金安全红线

## 案例 R-006 客服承诺超权限

**场景**：一线客服为安抚用户承诺「全额退款 + 200 元补偿」，超出权限。
**处理**：质检抽检发现录音 → 启动红线复核 → 主管与用户重新沟通（致歉 + 说明权限 + 按规则给 100 元封顶补偿）→ 当事客服按红线处理（记绩效）。
**风险点**：承诺超出权限属红线行为；平台兑现承诺会扩大损失，不兑现则失信——两边都输，只能防在前。
**依据**：POL-030、POL-032、《客服工作手册》红线

## 案例 R-007 跨境关税争议

**场景**：用户海淘化妆品被税，要求平台承担关税。
**处理**：核对贸易方式（保税仓直发，含税价）→ 说明「保税仓含税，个人行邮方式超额度才需缴税」→ 用户实际为个人行邮超出额度 → 解释政策并给出后续避税建议，不承诺退税。
**风险点**：跨境税收规则复杂，客服必须核对贸易方式再答复，不可想当然。
**依据**：POL-027

## 案例 R-008 安装事故（家电掉落）

**场景**：用户新装热水器使用中脱落，家中物品受损，要求赔偿。
**处理**：涉及人身财产安全 → 立即升级 L3 + 法务 → 安抚 + 登记损失清单 → 安装服务商责任认定（安装质量问题）→ 平台先行赔付（物品损失 + 换机）→ 向服务商追偿 + 暂停该服务商。
**风险点**：安全事故金额不定，一线禁止报价；先行赔付 + 追偿是标准动作。
**依据**：POL-016、《家居 SOP》3、《投诉升级 SOP》安全投诉

## 案例 R-009 用户要求删除个人信息

**场景**：用户要求删除账号及全部个人信息。
**处理**：登记删除请求 → 48 小时内提交数据管理组 → 按流程核实身份 → 数据删除/匿名化处理后回执用户 → 告知「删除后无法恢复」。
**风险点**：个人信息删除必须走正式流程留痕；客服端不直接删库。
**依据**：POL-024

## 案例 R-010 疑似套现（退款不退货）

**场景**：用户申请「仅退款」但拒绝退货，主张「懒得寄，平台直接退吧」。
**处理**：无理由退款必须退货 → 拒绝仅退款 → 用户坚持 → 转人工核查订单与退款历史 → 正常诉求引导退货，异常标记风控。
**风险点**：「仅退款不退货」是套现高发区；规则内必须退货才能退款（生鲜坏损等合规场景除外）。
**依据**：POL-001、《退款 SOP》资金安全红线

## 案例 R-011 用户过激言论

**场景**：用户退款被拒后在对话中辱骂客服。
**处理**：客服不还口 → 共情安抚 → 说明规则 → 用户持续过激 → 转接主管（不挂机冲突）→ 录音留证，按规则给出可执行方案。
**风险点**：还嘴即红线；过激用户要「先处理情绪」。
**依据**：POL-032、《客服工作手册》4

## 案例 R-012 系统错误导致超卖

**场景**：大促期间某爆款超卖 300 单，用户订单被取消。
**处理**：批量致歉 + 主动通知 → 全额退款 + 30 元券补偿 + 优先补货资格 → 涉及已扣款未到账的优先处理 → 复盘系统防超卖规则。
**风险点**：超卖属于平台责任，补偿标准统一，防止用户间「补偿不公」引发次生投诉。
**依据**：《订单与支付 FAQ》库存与预售、《投诉升级 SOP》
