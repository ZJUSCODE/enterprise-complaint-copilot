# 客诉 Copilot 前端产品化设计

## 目标

把当前前端从“求职作品集”表达改为真实的企业客诉运营工作台。外部访问者只看到业务价值、处置流程和系统能力；面试现场仍能用最短路径展示 SQL、SOP RAG、Guardrail、人工复核与审计链路。

## 范围

- 重构 `/public` 的定位、能力说明和入口文案。
- 删除前端中的 `Portfolio`、面试讲解、Roadmap、P0/P1/P2 和开发进度表达。
- 把首页演示脚本改造成可实际点击的“标准处置流程”。
- 把工程能力卡改成业务与治理能力，不暴露项目开发过程。
- 保持现有路由、权限、API、查询 prompt 和核心交互不变。

## 页面设计

### 公开页

公开页定位为“智能客诉运营平台”的产品入口。

- Hero 首屏说明风险识别、证据核验、处置建议和人工复核的业务闭环。
- 主操作进入登录页；次操作进入处理台并沿用现有鉴权跳转。
- 四项能力改为风险识别、智能处置、权限控制、全程追溯。
- Roadmap 区域替换为三步业务闭环：发现风险、核验证据、复核留痕。
- 不出现求职、作品集、面试、简历、Demo、P0/P1/P2 等表达。

### 今日作战台

- “演示路径 / 面试时按这个顺序讲”改为“标准处置流程 / 按证据链完成处理”。
- 保留四个一键入口及原有 prompt，让现场操作速度不受影响。
- 代码变量 `demoRunbook` 改为业务语义名称 `handlingPlaybook`。
- 能力卡改为风险聚合、证据驱动、受控执行和闭环治理。

### 导航与视觉

- 导航保持紧凑工作台结构，不增加营销页导航。
- 保持当前黑、白、灰与绿色状态色，不引入新视觉体系。
- 桌面和移动端沿用现有响应式规则，避免扩大改动范围。

## 数据与错误处理

本次不修改 API、Pinia store、鉴权和后端数据结构。公开页是静态产品说明；今日作战台继续使用现有 loading、error、fallback 和权限状态。

## 验证

- 全前端搜索不再出现求职、面试、简历、Portfolio 和开发阶段标签。
- `npm run build` 通过 TypeScript 与 Vite 构建。
- Playwright 覆盖公开页、登录页和登录后的首页核心入口。
- 检查 1440 x 1000 与 390 x 844 截图，确认无文本溢出、重叠或布局跳动。
- 后端快速检查继续通过，证明前端文案重构未影响演示链路。

## 非目标

- 不删除仓库中的求职版 README 或面试文档；用户要求只清理前端页面。
- 不改写 Agent、RAG、SQL、Guardrail、审计或复核逻辑。
- 不新增后端接口、用户角色或业务数据。
